# New Horizon Thin Client

This module is the isolated runtime for the low-memory client. It does not load
Minecraft or Forge classes. The existing Forge profile remains the functional
fallback while this runtime is built incrementally.

The core follows three non-negotiable rules:

1. Anonymous memory is admitted through explicit category budgets.
2. Network, world and mesh queues have fixed capacities and backpressure.
3. Immutable assets stay in read-only file-backed mappings and are decoded on
   demand instead of becoming a permanent Java object graph.

WebDisplays compatibility is implemented at the protocol and behavior level.
The Android Gecko bridge and LTW renderer remain shared with the existing app;
Forge mod JARs are never loaded into this runtime.

## Audio (component 74)

The audio worker uses the original Minecraft 1.20.1 OGG objects from `--assetsDir`,
with a compact generated event/weight/block-SoundType catalog. OpenAL and Vorbis
run on a dedicated worker; every sound is streamed through fixed native arenas
and PCM queues, with 24 simultaneous voices and an 18 MiB AUDIO admission budget.
This reservation is not a measurement or hard limit on the whole process RSS.
No Minecraft or Forge classes are loaded for audio. Existing `options.txt`
master/category sliders are read at startup.

The catalog is generated by `tools/VanillaSoundDump1201.java` (official runtime
registry/SoundType extraction) and `tools/generate_sound_catalog_1_20_1.py`
(official asset index, sounds.json, block reports and tags). Audio objects stay
in the launcher's existing asset cache, outside the component JAR/APK.

`selfTest` covers catalog counts, deterministic selection, PCM conversion,
listener orientation, packet parsing, queue saturation/stop priority, options,
and server biome/damage registry NBT. `tools/ThinAudioNativeTest.java` additionally
decodes all 3,395 OGG files with desktop LWJGL natives and tests OpenAL playback,
source saturation, stop/reset cleanup and ambient crossfades on the null driver.

Current coverage and remaining parity gaps are recorded in
`codex-work/thin-v74-audio/STATUS.md`. Component 74 is an audio implementation for
testing, not a certification of complete vanilla audiovisual parity.
